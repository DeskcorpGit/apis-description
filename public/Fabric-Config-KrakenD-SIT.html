01
Contexto — O que muda

Hoje o Fabric chama os parceiros externos diretamente. Com o KrakenD, o Fabric passa a chamar o gateway, que encaminha para os parceiros. O app continua funcionando normalmente — a mudança é apenas nas URLs de backend configuradas no Fabric.

Fluxo atual

Appusuário
→
Fabricbackend do app
→
Corebanx / IDVerse
NeoBiz / AuthCubedireto no parceiro

Fluxo com KrakenD

Appusuário
→
Fabricbackend do app
→
KrakenD EE 2.13.2API Gateway · SIT
→
Corebanx / IDVerse
NeoBiz / AuthCubevia gateway

Passos para o Teste
  • 1Alterar as URLs nos arquivos Endpoints/default.xml de cada serviço conforme a seção 03
  • 2Alterar os paths nas operações Operations/*.xml conforme as tabelas
  • 3Publicar/republicar os serviços alterados no Fabric
  • 4Confirmar health check do KrakenD: GET .../health → {"status":"ok"}
  • 5Abrir o app e executar o fluxo de onboarding normalmente
  • 6Acompanhar os logs do KrakenD com o time de Arquitetura em paralelo
